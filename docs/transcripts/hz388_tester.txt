  - Output:
    - `simulator exit=0`
    - `preprocess exit=0`

- Expected vs actual:
  - Expected: all five long-running services stop cleanly in Compose.
  - Actual: dashboard exits with SIGKILL/137 while the others are clean.
- Minimal fix:
  - Wrap the dashboard command in a small shell wrapper that traps SIGTERM/SIGINT and `exec`s the Streamlit process, or use a dedicated entrypoint script. The current direct `streamlit run ...` does not exit cleanly under Compose stop.

### Blocking issue 2: same-second checkpoints overwrite each other
- Severity: high
- Evidence:
  - Runtime check:
    - `CASE_SAME_SECOND_PATHS checkpoint_20240101_000000.joblib checkpoint_20240101_000000.joblib True True True`
  - Code: `train.py:34-49`
- Expected vs actual:
  - Expected: two separate checkpoints written in the same second produce distinct names.
  - Actual: both generate the same filename because the stamp is second-resolution only.
- Minimal fix:
  - Add microseconds to the checkpoint stamp, e.g. `"%Y%m%d_%H%M%S_%f"` or add sequence-safe naming. This aligns with the raw/feature file naming style and prevents overwriting.

## 6) Operational concerns the plan may have missed

### Disk usage grows without retention policy
- Severity: medium
- Evidence:
  - `simulator.py:86-103` writes raw CSVs and never removes them.
  - `preprocess.py:123-145` writes a feature file for every processed raw file and keeps `.done_` markers.
  - `train.py:34-49` writes every checkpoint forever; `state` keeps the latest checkpoint name only, but previous checkpoint files accumulate.
  - `infer.py:76-105` writes predictions with timestamps in the filename and never rotates them.
  - `preprocess.py:90-120` appends `batch_quality.csv` forever.
- Expected vs actual:
  - Expected: a demo stack is okay for short-lived classroom use.
  - Actual: long-running operation will steadily increase disk usage on the named volume with no pruning or retention policy.
- Minimal fix:
  - Add retention policy (max age, max file count, or delete old raw/feature/prediction/checkpoint files after a threshold), and a separate capped quality log or rotation.

### Relative path ambiguity for DATA_ROOT
- Severity: medium
- Evidence:
  - `paths.py:26-33`
- Expected vs actual:
  - `DATA_ROOT=relative-data` is accepted as a literal relative path, which may be surprising when run from a different working directory.
  - This isn’t a crash, but it is a footgun for operational deployments.
- Minimal fix:
  - Resolve relative `DATA_ROOT` against the project root or reject it early with a clear error.
